argot is a statistical linter: it will sometimes learn from the wrong files, or
flag a line you meant to write. Every one of those is fixable, and every fix is
plain text you commit alongside your code. There are two separate concerns:

- **Scope** — *what argot learns from and looks at.* Controlled by
  `.argotignore` (and the built-in defaults).
- **Mutes** — *specific hits you've judged fine.* Controlled by inline comments
  and `.argot/suppressions.yaml`.

Each surface below opens with its **Location** and a single copy-pasteable
example that exercises every knob it has. A [reference table](#which-files-argot-writes-and-where)
at the end lists every file argot writes and whether it's committed.

## What argot ignores by default

Without any config, argot applies the **`argot:recommended`** set — the
directories and files that are almost never part of a repo's authored voice:

- **Directories** (matched at any depth): `test/` `tests/` `__tests__/` (and any
  dir whose name starts with `test`), `doc/` `docs/` `example/` `examples/`
  `migration/` `migrations/` `benchmark/` `benchmarks/` `fixtures/` `scripts/`
  `build/` `dist/` `__pycache__/` `.git/` `.history/` `.tox/` `.eggs/`.
- **Files:** `test_*` and `conftest.py`; any name containing `.test.`, `.spec.`,
  or `.config.` (so `x.test.ts`, `vite.config.ts`); and dotfile `rc.` configs
  (`.babelrc.js`).
- **Structural:** any file whose header carries an auto-generation marker
  (`@generated`, "Code generated by …") or that is ≥ 80% static data literals
  (locale tables, fixture arrays). These are detected per file, in any
  directory.

The same resolved set governs what argot **learns** from, **calibrates** on, and
**checks** — they never drift apart.

## `.argotignore` — set the scope

**Location:** `<repo-root>/.argotignore` (beside your top-level `.gitignore`).
It's your config — commit it so the whole team and CI share the same scope.

A gitignore-style file, layered **on top of** `argot:recommended`. Use it for the
directories only you can name — generated clients, vendored SDKs, legacy modules.
This example exercises every pattern form argot supports:

```gitignore
# .argotignore — gitignore-style. Blank lines and #-comments are ignored.
# Every pattern below ADDS to the built-in argot:recommended set.

legacy                 # bare name → a dir/file named `legacy` at ANY depth
vendor/                # trailing slash → that directory only, never a `vendor` file
/generated.py          # leading slash → anchored to the repo root (this file only)
src/proto/             # an interior slash also anchors to the root
src/*.gen.ts           # `*` matches within ONE segment (does not cross `/`)
data/shard-[0-9].bin   # `[…]` → one char from a set/range (shard-0.bin … shard-9.bin)
config/env.?.local     # `?` → exactly one character

**/snapshots/**        # `**` spans directories, at any depth

*.min.js               # bundled/minified output, anywhere
!keep.min.js           # `!` re-includes a path an earlier pattern excluded (last match wins)
```

The rules, precisely:

- `*`, `?`, and `[…]` match within a path segment; `**` spans directories.
- A leading `/` — or **any interior `/`** — anchors the pattern to the repo root;
  a bare name (`legacy`) matches at any depth.
- A trailing `/` (`vendor/`) matches a directory and everything under it, never a
  same-named file.
- A leading `!` re-includes a path an earlier pattern excluded — **last match
  wins.** Blank lines and `#` comments are ignored.

Don't hand-guess the directories to exclude — [`argot init --suggest`](/docs/setup/) surfaces the
generated/data-heavy ones with evidence, and an agent can name the vendored/legacy ones from your
tree. See [Setup](/docs/setup/).

To start from scratch instead of adding to the defaults, disable them with a
single line — then only your own patterns apply:

```gitignore
!argot:recommended
```

## Inline comments — mute one line

**Location:** in the source file itself, on the line above the code (or around
the block) you're excusing. The comment token is the language's own line comment:
**`#` for Python and Ruby, `//` for everything else** (TypeScript/JavaScript, Go,
Rust, C, C++, Java, C#, PHP) — the language adapter supplies it.

When an exception is deliberate, say so where it lives. This block uses every
form:

```python
# argot: ignore-next-line — vendored oddity we keep on purpose
weird_call()

# argot: ignore-next-line scorer=import — deliberate one-off dependency
import boto3

# argot: ignore-block-start — legacy shim, do not judge this region
legacy_thing()
more_legacy()
# argot: ignore-block-end
```

The `//` languages are identical, just with a different token:

```ts
// argot: ignore-next-line scorer=bpe - generated glue, keep as-is
oddPhrasing();
```

The rules:

- **A reason is mandatory.** A suppression comment without one is reported as a
  warning and ignored (it's also the note your future self reads). Separate the
  reason from the directive with `—`, `-`, or `:`.
- **`scorer=<name>`** (optional) scopes the mute to one signal — `bpe`, `import`,
  or `call_receiver`. Omit it to mute the hunk whatever fired. An unknown scorer
  name is a warning, and the directive is ignored.
- **`ignore-next-line`** mutes the single line below the comment.
  **`ignore-block-start` … `ignore-block-end`** mute everything between them
  (the `-end` needs no reason). An unclosed block suppresses to end of file with
  a warning.

## Durable mutes — accept a specific hit

**Location:** `<repo-root>/.argot/suppressions.yaml`. `argot mute` appends here;
you can also hand-edit it. It is **committed** — the one file under `.argot/`
that argot's own `.gitignore` keeps tracked — so a mute is a shared, reviewable
audit trail that a teammate and CI inherit.

Every hit prints a stable `[hash]`. To accept it for good, mute the hash:

```text
argot mute a1b2c3d4e5f6 --reason "adopting axios repo-wide"
argot mute a1b2c3d4e5f6 --reason "temporary shim" --expires 30d
```

`--reason` records why (recommended everywhere argot reports a hit); `--expires`
takes a **day count** (`30d`, or a bare `30`), which argot resolves to a calendar
date in the file. `mute` reads the last `check` run to learn which file the hash
belongs to, so run `argot check` first.

Review and prune what you've muted:

```text
argot list-mutes            # every active suppression, across all three surfaces
argot review-mutes          # report hash-scoped mutes whose file is gone
argot review-mutes --prune  # …and rewrite suppressions.yaml to drop the dead ones
```

`review-mutes` flags a hash-scoped mute as **dead** once the file it names no
longer exists (in the working tree or `HEAD`) — the point at which it can never
fire again. `--prune` drops only those; a mute guarding a file you still have is
always kept.

### The `suppressions.yaml` format

The file is a **top-level YAML list of rules**. `argot mute` appends one textual
list item, so comments and hand-written entries are never rewritten by a mute.
This example shows every field a rule can carry:

```yaml
# .argot/suppressions.yaml — plain YAML, hand-editable, committed.
- path: "src/vendored/**"     # REQUIRED — glob (fnmatch; `*` crosses `/`)
  scorer: bpe                 # optional — bpe | import | call_receiver (scope to one signal)
  hash: a1b2c3d4e5f6          # optional — pin to one specific hit (argot mute writes this)
  expires: 2026-12-31         # optional — YYYY-MM-DD; the rule is ignored ON/AFTER this date
  reason: vendored upstream   # REQUIRED — why (surfaces in list-mutes and code review)

# A hand-written rule needs only path + reason — it then covers every hit under the glob:
- path: "generated/**"
  reason: protobuf stubs, never our voice
```

Only `path` and `reason` are mandatory. A rule with a missing/invalid field (no
`path`, no `reason`, an unknown `scorer`, a malformed `expires`) is skipped with a
warning on stderr — one bad entry never voids the file. `expires` is a calendar
date: an entry with `expires` in the past is treated as expired and ignored; an
entry expiring **today** is still active. (The `argot mute --expires 30d` day
count is converted to this `YYYY-MM-DD` form when written.)

## Which files argot writes, and where

Everything argot writes lives under `.argot/` at the repo root. Only two files
are meant to be committed — your scope config (`.argotignore`, above) and your
mute list (`suppressions.yaml`). Everything else is a rebuildable artifact that
`argot fit` regenerates in seconds, so `init`/`fit` drop a `.argot/.gitignore`
that keeps it all out of version control.

| File | Written by | What it is | Committed? |
|---|---|---|---|
| `.argotignore` *(repo root)* | you / an agent | Scope config — dirs & files to exclude. | **Yes** — commit it. |
| `.argot/suppressions.yaml` | `argot mute` (or by hand) | Durable mute list — accepted hits + reasons. | **Yes** — the audit trail. |
| `.argot/scorer-config.json` | `fit` / `init` | The fitted voice model: calibrated threshold(s) + scorer config. | No — rebuildable. |
| `.argot/manifest.json` | `fit` / `init` | Versioned, hashed record of what was learned (model hash, fit commit, corpus size); read by `inspect --model`. | No — rebuildable. |
| `.argot/repo-corpus.txt` | `fit` / `init` | The source files counted into the repo distribution. | No — rebuildable. |
| `.argot/generic-baseline.json` | `fit` / `init` | The bundled generic-baseline reference. | No — rebuildable. |
| `.argot/dataset.jsonl` | `extract` | Raw training dataset — one record per hunk. The check path doesn't need it. | No — rebuildable. |
| `.argot/last-check.json` | `check` | Cache of the last check's hits, so `argot mute <hash>` can resolve. | No — rebuildable. |
| `.argot/.gitignore` | `fit` / `init` | Ignores everything under `.argot/` **except** `suppressions.yaml`. | Ignores itself; regenerated by `fit`/`init`. `git add -f .argot/.gitignore` to share it. |

Want to commit the model yourself instead? Delete `.argot/.gitignore` and it
stays out of your way — CI otherwise restores the model from cache or re-fits.

## Which to reach for

| You want to… | Use |
|---|---|
| Stop argot learning from a directory | `.argotignore` |
| Start the defaults over | `!argot:recommended` in `.argotignore` |
| Accept one deliberate line | inline `# argot: ignore-next-line — reason` |
| Accept a specific reported hit for good | `argot mute <hash> --reason …` |
| Temporarily silence a hit | `argot mute <hash> --expires 30d` |
| Cover many hits under one path | a `path:` glob rule in `suppressions.yaml` |

Suppressed ≠ deleted: `check` drops muted hits from its output and exit code but
still prints a one-line count on stderr, so a repo full of silent mutes never
looks cleaner than it is.
