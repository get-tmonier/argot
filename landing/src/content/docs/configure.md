argot is a statistical linter: it will sometimes learn from the wrong files, or
flag a line you meant to write. Every one of those is fixable, and every fix is
plain text you commit alongside your code. There are two separate concerns:

- **Scope** — *what argot learns from and looks at.* Controlled by
  `.argotignore` (and the built-in defaults).
- **Mutes** — *specific hits you've judged fine.* Controlled by inline comments
  and `.argot/suppressions.yaml`.

## What argot ignores by default

Without any config, argot applies the **`argot:recommended`** set — the
directories and files that are almost never part of a repo's authored voice:

- **Directories:** `test/` `tests/` `__tests__/` `docs/` `examples/`
  `migrations/` `benchmarks/` `fixtures/` `scripts/` `build/` `dist/`
  `__pycache__/` `.tox/` `.eggs/` `.history/` (and more).
- **Files:** `test_*`, `*.test.*`, `*.spec.*`, `conftest.py`, `*.config.*`,
  and dotfile `rc.` configs.
- **Structural:** any file whose header carries an auto-generation marker
  (`@generated`, "Code generated by …") or that is ≥ 80% static data literals
  (locale tables, fixture arrays). These are detected per file, in any
  directory.

The same resolved set governs what argot **learns** from, **calibrates** on, and
**checks** — they never drift apart.

## `.argotignore` — set the scope

A gitignore-style file at your repo root, layered **on top of**
`argot:recommended`. Use it for the directories only you can name — generated
clients, vendored SDKs, legacy modules:

```gitignore
# Generated gRPC/protobuf stubs — not our voice
src/generated/
# Vendored Stripe client, checked in
third_party/stripe/
# Frozen 2019 module, kept for reference only
legacy/
```

Don't hand-guess these — [`argot init --suggest`](/docs/setup/) surfaces the
generated/data-heavy directories with evidence, and an agent can name the
vendored/legacy ones from your tree. See [Setup](/docs/setup/).

To start from scratch instead of adding to the defaults, disable them with a
single line and list your own:

```gitignore
!argot:recommended
```

### The model directory is not source

`argot fit`/`init` write a rebuildable model into `.argot/`, and `init` drops a
`.argot/.gitignore` so it (and the heavy `argot extract` dataset) never gets
committed. Regenerate it any time with `argot fit`; CI restores it from cache or
re-fits. Delete that `.gitignore` if you'd rather commit the model yourself.

## Inline comments — mute one line

When a single line is a deliberate exception, say so where it lives. The token
is language-aware (`#` for Python/Ruby, `//` for TS/Go/Rust/…):

```python
# argot: ignore-next-line — vendored oddity we're keeping on purpose
weird_call()
```

Scope it to one scorer, or mute a whole block:

```ts
// argot: ignore-next-line scorer=bpe — generated glue
oddPhrasing();

// argot: ignore-block-start — legacy shim, do not judge
legacyThing();
moreLegacy();
// argot: ignore-block-end
```

A reason (after `—` or `-`) is encouraged — it's the note your future self reads.

## Durable mutes — accept a specific hit

Every hit prints a stable `[hash]`. To accept it for good, mute the hash — argot
appends a scoped rule to `.argot/suppressions.yaml`:

```text
argot mute a1b2c3d4e5f6 --reason "adopting axios repo-wide"
argot mute a1b2c3d4e5f6 --reason "temporary" --expires 30d
```

This is the recommendation everywhere argot reports a hit — in the terminal, in
CI, in the agent skills: *if it's intentional, mute it with a reason.* The rule
is committed, so it doubles as an audit trail of a deliberate decision, and the
noise never comes back.

Review and prune what you've muted:

```text
argot list-mutes            # every active suppression, across all three surfaces
argot review-mutes --prune  # drop mutes whose hits no longer fire
```

## Which to reach for

| You want to… | Use |
|---|---|
| Stop argot learning from a directory | `.argotignore` |
| Start the defaults over | `!argot:recommended` in `.argotignore` |
| Accept one deliberate line | inline `# argot: ignore-next-line` |
| Accept a specific reported hit for good | `argot mute <hash> --reason …` |
| Temporarily silence a hit | `argot mute <hash> --expires 30d` |

Suppressed ≠ deleted: `check` drops muted hits from its output and exit code but
still prints a one-line count on stderr, so a repo full of silent mutes never
looks cleaner than it is.
